# 限速策略组设计

本文档描述已确认的“限速策略组”业务模型。当前代码尚未落地该能力；本文用于固定后续实现边界，避免重新回到旧的分组内嵌限速设想。

## 1. 目标

- 把“登录领配置的分组”和“流量治理的策略”彻底拆开。
- 允许先创建空的限速策略组，再在后续绑定已有隧道。
- 同时支持：
  - 独享模式
  - 共享模式
- 固定上下行分离，不做上下行共享桶。
- 初版先只覆盖单端口 TCP / UDP 隧道。

## 2. 非目标

- 不把限速重新挂回 `proxy_groups` 上演进。
- 不支持 TCP range / UDP range 隧道参与限速策略。
- 不做一个隧道绑定多个限速策略组。
- 不做策略叠加、优先级链、条件匹配和继承体系。
- 不做旧版本兼容层。

## 3. 资源模型

### 3.1 `proxy_groups`

`proxy_groups` 继续只负责：

- 登录
- 认证
- 领取配置
- 在线会话归属
- 隧道归属

它不再承载正式的限速策略模型。

### 3.2 `tunnels`

`tunnels` 继续表示真实转发对象。

每条隧道：

- 仍然必须从属于一个 `proxy_group`
- 后续可以选择绑定到一个 `rate_policy_group`
- 也可以不绑定任何限速策略组

### 3.3 `rate_policy_groups`

新增独立资源 `rate_policy_groups`。

它的职责只有：

- 保存限速策略参数
- 保存策略模式
- 承接隧道绑定

它不从属于任何 `proxy_group`，因此允许：

- 在没有任何代理分组时先创建
- 在没有任何隧道时先创建空策略组

## 4. 绑定关系

策略绑定应作为独立关系表达，语义如下：

- 一个 `rate_policy_group` 可以绑定 `0..n` 条隧道
- 一个隧道最多只能绑定 `1` 个 `rate_policy_group`
- 一个隧道也可以不绑定任何限速策略组

衍生约束：

- 隧道必须先存在，才能被绑定
- 删除隧道时，其绑定必须自动删除
- 删除代理分组时，其下隧道和对应绑定一起删除，但限速策略组本体保留
- 删除仍有绑定的限速策略组时，默认应拒绝，要求先解绑或迁移

## 5. 策略模式

限速策略组固定支持两种模式：

- `independent`
- `shared`

### 5.1 独享模式

独享模式的语义是：

- 同一策略组中的所有已绑定隧道共享同一套参数
- 但每条隧道各自持有自己的令牌桶
- 隧道之间互不争抢

例如：

- 策略组 `A`
- 模式 `independent`
- 下行 `10 Mbps`
- 上行 `5 Mbps`
- 绑定 `T1 T2 T3`

则最终效果是：

- `T1` 自己有 `10 Mbps` 下行桶和 `5 Mbps` 上行桶
- `T2` 自己有 `10 Mbps` 下行桶和 `5 Mbps` 上行桶
- `T3` 自己有 `10 Mbps` 下行桶和 `5 Mbps` 上行桶

### 5.2 共享模式

共享模式的语义是：

- 同一策略组中的所有已绑定隧道共用一组令牌桶
- 下行共享一只桶
- 上行共享一只桶

例如：

- 策略组 `B`
- 模式 `shared`
- 下行 `30 Mbps`
- 上行 `15 Mbps`
- 绑定 `T4 T5`

则最终效果是：

- `T4 + T5` 共抢 `30 Mbps` 下行桶
- `T4 + T5` 共抢 `15 Mbps` 上行桶

## 6. 共享模式边界

共享模式初版只允许在同一个 `proxy_group` 内共享。

因此：

- 空的共享策略组在未绑定任何隧道前，不带代理分组归属
- 当它绑定第一条隧道后，归属锁定为该隧道所属的 `proxy_group`
- 后续只能继续绑定同一代理分组下的隧道
- 当所有绑定全部清空后，这个锁定解除

独享模式不受这个约束；它可以绑定来自不同代理分组的单端口隧道，因为它本质上只是复用同一套参数模板。

## 7. 支持范围

初版只支持单端口隧道：

- TCP 单端口
- UDP 单端口

初版明确不支持：

- TCP range
- UDP range

对应业务规则：

- 范围隧道不进入“可绑定隧道”列表
- 已绑定策略的单端口隧道，如果要改成范围隧道，应先解绑

## 8. 执行粒度

初版执行粒度固定为：

- 一条隧道记录 = 一个限速执行单元

由于范围隧道当前不纳入限速策略，初版不讨论“范围内每个端口单独一桶”。

## 9. 上下行语义

上下行固定分离，不做共享：

- 下行：公网客户端 -> `frps` -> `frpc` -> 本地服务
- 上行：本地服务 -> `frpc` -> `frps` -> 公网客户端

每个策略组都必须明确持有两套方向参数：

- `downlink`
- `uplink`

无论是独享模式还是共享模式，都固定为：

- 下行一套桶
- 上行一套桶

不做“上下行共用一个总桶”的模型。

## 10. 速率单位

速率语义基础单位固定为：

- `bps`

对外录入和展示规则固定为：

- 最小单位 `K`
- 默认单位 `M`
- 最大单位 `G`

对应语义：

- `Kbps`
- `Mbps`
- `Gbps`

例如：

- `10 Mbps = 10,000,000 bps`

因此，业务层应统一把“单位展示”和“内部基础单位”分开：

- 业务输入输出使用 `K/M/G`
- 实际语义统一归一到 `bps`

## 11. 管理流程

策略组主流程固定为：

1. 创建限速策略组
2. 选择模式：`independent` 或 `shared`
3. 设置上行和下行速率
4. 在后续任意时点绑定已有单端口隧道
5. 可继续修改参数、解绑、迁移绑定

这意味着：

- 可以先创建空策略组
- 后续再补代理分组和隧道
- 再把已有隧道绑定到合适的策略组

## 12. 与当前代码的关系

当前正式 schema 中已经不再保留旧的 `proxy_groups.rate_limit` 字段。

后续正式实现限速时，应直接围绕：

- `rate_policy_groups`
- 策略与隧道绑定关系
- 独享 / 共享模式
- 上下行分离

推进，而不是重新把限速收回 `proxy_groups`。
