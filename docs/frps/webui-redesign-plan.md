# frps WebUI 最小基线

更新时间：2026-04-20

当前状态：旧版 WebUI 已清空。本文档只固定重新开始时的最小技术栈、必要功能和开发边界，不再描述已经删除的旧页面结构、壳层布局或视觉方案。

## 1. 技术基线

- WebUI 仍作为 `frps/webui/` 下的独立前端目录维护。
- 开发和构建环境固定为 `Node.js + npm`。
- 前端框架固定为 `Vue 3`。
- UI 组件库固定为 `Element Plus`。
- 构建产物仍输出到 `frps/webui/dist/`，由 `frps` 按 `webui.dist_dir` 托管。

## 2. 目标与边界

- 只为当前已经存在的管理 API 提供最小可用管理面。
- 不改后端 API、认证算法、Cookie 会话模型、数据库 schema 和控制协议。
- 不预埋未来功能，不添加日志页、监控页、连接管理页、说明页或占位导航。
- 不先做复杂壳层、设计系统和视觉实验，先把必要功能跑通。

## 3. 必要功能

- 管理密钥初始化
- challenge 登录
- 会话状态检查与退出登录
- 分组列表、新建、编辑、删除、重置 token
- 隧道列表、新建、编辑、删除
- 基础加载态、空态、错误提示和最小表单校验

## 4. 最小页面

- `/init`
  - 只负责一次性初始化管理密钥。
- `/login`
  - 只负责 challenge 登录。
- `/proxy-groups`
  - 作为最小管理主页面，承接分组和隧道的必要管理功能。
- 是否保留 `/` 概览页不作为当前硬要求；如果没有实际内容，可以直接把根入口回到主管理页。
- `/tunnels` 不要求单独存在；如需兼容旧入口，只做跳转或复用，不再单独设计第二套界面。

## 5. 页面表达约定

- 登录页只保留标题、输入框、按钮和必要报错。
- 管理页优先使用表格、表单、弹窗和抽屉，不堆叠大段说明文案。
- 分组和隧道围绕真实字段做最小展示，不包装未来能力。
- `token_secret` 只在创建或重置时显示一次，列表和详情只保留 `token_id`。
- UI 中不开放 `rate_limit`、`capture_enabled`、`group_tunnel_ip_rules` 等未进入真实运行时的字段。

## 6. 代码组织建议

- 目录只保留最小必需结构，例如 `src/main`、`src/router`、`src/api`、`src/views`。
- 只有在确实复用时才增加 `src/components` 或状态管理层。
- 不提前拆复杂 composables、主题系统或业务框架。
- 组件命名和页面拆分以“能直接对应 API 和业务动作”为准。

## 7. 开发约定

- 当前目录如果还是空的，先补 `package.json`、基础入口和最小页面，不先追求完整框架。
- Node.js 环境建议使用 `20+`，npm 建议使用 `10+`。
- Windows PowerShell 下前端命令优先使用 `npm.cmd`。
- 重建完成后，开发/构建命令统一收口为：

```powershell
cd frps/webui
npm.cmd install
npm.cmd run dev
npm.cmd run build
```

后续如果继续扩展 WebUI，先更新本文档的“必要功能”和“边界”，再进入实现。
