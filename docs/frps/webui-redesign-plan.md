# frps WebUI 当前管理基线

更新时间：2026-04-20

当前状态：本文档记录已经落地到当前代码的 WebUI 管理基线。后续前端迭代默认在这个基线之上继续收紧，不再把本文当作待实现的临时方案。

## 1. 定位与硬边界

当前 WebUI 只表达已经进入真实代码与接口契约的能力：

- 不改后端 API、认证算法、challenge 登录语义和 Cookie 会话模型。
- 不改数据库 schema、控制协议、现有 CRUD 接口契约和真实能力边界。
- 不把未来能力包装成当前导航或占位页面。
- 当前真实业务范围仍然只有管理认证、分组 CRUD、token 重置、隧道 CRUD，以及 TCP/UDP 单端口与连续范围映射。

当前已登录管理态的一级导航固定为两项：

- `/`：概览
- `/proxy-groups`：接入管理

`/tunnels` 继续保留兼容访问路径，但只复用同一张接入管理页，不再作为一级导航独立存在。

## 2. 管理壳层基线

当前管理壳层结构如下：

```text
app-shell
├─ shell-sidebar
│  ├─ brand
│  └─ primary-nav
└─ shell-stage
   ├─ shell-topbar
   ├─ shell-alert-slot
   └─ shell-content
      └─ page-shell
```

当前壳层职责固定如下：

- `shell-sidebar`
  - 只承接品牌和一级导航，不再放常驻说明卡或操作指南。
- `shell-topbar`
  - 只承接当前路由标题、简短说明、认证状态、会话到期信息和全局会话动作。
  - 顶栏保持薄条形态，不再堆叠大段描述。
- `shell-alert-slot`
  - 只承接认证或全局状态类告警。
- `shell-content`
  - 作为宽主内容区容器，优先把横向空间留给中间业务表格和配置表单。

当前视觉方向已经固定为更收紧的单侧导航管理布局：

- 左侧边栏更窄，导航直接贴住侧栏。
- 顶部条更薄，信息密度高于说明密度。
- 主内容区使用更宽的流式容器。
- 页面内部不再依赖“大 hero + 常驻右侧说明栏”的说明式结构。

## 3. 导航与路由约定

当前导航与路由表达固定如下：

- 一级导航统一从 `webui/src/router/index.ts` 的路由元数据生成。
- `AppShellView.vue` 不手写业务路由列表，只消费统一导航元数据。
- `/proxy-groups` 的标题、说明和导航标签都已经收口为“接入管理”。
- `/tunnels` 通过 `managementNavActiveName` 回落到 `proxy-groups` 的导航高亮与页面语义。
- 页面标题、眉标和描述都优先由路由元数据驱动，不在每个业务页里重复定义壳层级标题。

## 4. 认证页基线

认证页继续独立于管理壳层：

- `/init`
  - 只负责一次性初始化管理密钥。
- `/login`
  - 已收紧为极简认证入口，默认只保留大标题、管理密钥输入框、登录按钮和动态错误提示。

下面这些实现语义保持不变，只是页面表现层做了减法：

- challenge 请求与 proof 计算流程不变。
- 登录成功后的 redirect 逻辑不变。
- 未初始化时的路由守卫跳转不变。
- Cookie 会话模型不变。

## 5. 接入管理页基线

当前统一接入管理页采用上下主从结构：

```text
access-management-page
├─ page-header
├─ group-section
└─ tunnel-section
```

### 5.1 分组区

- 页面上半区负责分组列表、分组状态、`token_id` 摘要和分组级操作。
- 分组级操作继续包含新建、编辑、删除和重置 token。
- 分组行本身承担“切换当前上下文”的职责，当前选中态必须清晰可见。
- 列表页只展示 `token_id`，不会回显历史明文 token。

### 5.2 隧道区

- 页面下半区只展示当前选中分组下的隧道配置。
- 隧道区继续承接 TCP/UDP、单端口/范围映射、启停状态和编辑/删除操作。
- 新建隧道时，`group_id` 自动绑定到当前选中分组，不在该页里跨分组切换。

### 5.3 联动语义

- 页面首次加载且存在分组时，默认选中一个分组，避免隧道区长期空白。
- 刷新数据时，优先保留当前选中分组；只有该分组已不存在时才回退到其他分组。
- 删除当前选中分组后，选中态自动回退到相邻分组；如果已无分组，隧道区显示“需先创建分组”的空态。
- `/proxy-groups` 与 `/tunnels` 当前都复用同一套 `AccessManagementView.vue` 实现，不再维护两套业务界面。

## 6. 页面密度与响应式

当前页面取舍已经固定为“减少说明噪音，把空间还给管理对象”：

- 不再使用大段 hero 文案、流程说明块或常驻右侧说明栏。
- 页面摘要优先改成紧凑统计条、局部标签和短提示。
- 表格和表单尽量全宽展示，必要时允许横向滚动。
- 页面标题区只保留必要标题和动作，不再堆叠长副标题。

当前响应式方向如下：

- 桌面端
  - 固定左侧导航和宽主内容区。
  - 接入管理页保持“上方分组、下方隧道”的单列主轴。
- 平板端
  - 左侧导航继续存在，但宽度进一步压缩。
  - 工具条允许换行，表格继续使用横向滚动承接宽列。
- 手机端
  - 左侧导航折叠为抽屉。
  - 登录页保持单卡片单列。
  - 接入管理页仍保持先分组后隧道的顺序。

- `webui/src/views/AppShellView.vue`

  - 统一接入管理主页面。
- `webui/src/views/ProxyGroupsView.vue`

- `webui/src/views/TunnelsView.vue`
  - 兼容包装层，复用接入管理主页面。
- `webui/src/views/LoginView.vue`
