# frps WebUI 管理面板重构方案

更新时间：2026-04-20

## 1. 目标与硬边界

本轮只重构 `frps/webui` 的信息架构、布局和视觉表达，不改动下面这些边界：

- 不改后端 API、认证语义和现有路由路径。
- 不新增数据库字段、控制面协议或伪入口。
- 不把未来能力包装成当前已实现功能。
- 继续使用 Vue 3 + Vue Router + Pinia + Element Plus。

当前管理态页面仍然只有三类：

- `/`：管理概览
- `/proxy-groups`：分组管理
- `/tunnels`：隧道管理

认证页仍然独立于管理壳层：

- `/init`
- `/login`

## 2. 新版管理壳层

新版管理壳层只服务于已登录后的三张管理页，统一结构如下：

```text
app-shell
├─ shell-sidebar
│  ├─ brand
│  ├─ primary-nav
│  └─ shell-side-note
└─ shell-stage
   ├─ shell-topbar
   │  ├─ route-identity
   │  └─ session-actions
   ├─ shell-alert-slot
   └─ shell-content
      └─ page-shell
```

各区域职责固定如下：

- `shell-sidebar`
  - 承接品牌、环境提示和主导航。
  - 不承接业务表单、统计卡片或页面级操作按钮。
- `shell-topbar`
  - 承接当前路由标题、副标题、认证状态、会话到期信息和全局操作。
  - 全局操作只保留“刷新状态”“退出登录”这类真实存在且跨页通用的动作。
- `shell-alert-slot`
  - 承接管理认证或全局状态类提示，例如 `lastError`。
  - 不混放页面内部的业务错误。
- `shell-content`
  - 作为页面容器，统一宽度、内边距、滚动节奏和响应式断点。
  - 只渲染当前路由页面骨架，不负责页面内部 CRUD 细节。

## 3. 导航结构

新版导航不新增路由，只重组现有入口的表达方式。

### 3.1 一级导航

- 概览
  - 路径：`/`
  - 角色：系统状态总览、风险提醒、快捷入口
- 分组管理
  - 路径：`/proxy-groups`
  - 角色：管理接入分组、启停状态和 token 生命周期
- 隧道管理
  - 路径：`/tunnels`
  - 角色：管理 TCP/UDP 单端口与范围映射

### 3.2 导航展示约定

- 侧边栏导航来源统一收口到一份路由元数据，不再在模板里手写分散链接。
- 当前激活路由使用高亮底色、左侧强调条或高对比边框表达，不只依赖文字颜色变化。
- 侧边栏底部保留一块只读说明区，用来提示当前管理面的真实能力边界，例如“当前只支持概览 / 分组 / 隧道三类页面”。

## 4. 顶部状态区

顶部状态区是新版壳层的核心收束点，统一包含两部分：

### 4.1 路由身份区

- 页面眉标
- 页面标题
- 一句页面说明

这三项应由路由元数据驱动，而不是每个页面自行重复写壳层级标题。

### 4.2 会话操作区

- 管理认证状态标签
- 会话到期时间
- “刷新状态”按钮
- “退出登录”按钮

如果后续增加更多全局状态，只能放这里或侧边栏说明区，不能再把同类状态散落到每个页面头部。

## 5. 通用页面骨架

三张管理页共享同一套页面骨架，统一结构如下：

```text
page-shell
├─ page-header
│  ├─ page-copy
│  └─ page-actions
├─ page-feedback
├─ page-metrics
└─ page-body
   ├─ page-main
   └─ page-side
```

各区域约定如下：

- `page-header`
  - 承接页面自己的标题补充文案和动作区。
  - 页面级主按钮统一放在这里，不再散落在 hero 卡片和表格 header 两处重复出现。
- `page-actions`
  - 放当前页最重要的 1 到 2 个动作。
  - 当前真实动作主要是“新建”“刷新”。
- `page-feedback`
  - 放页面业务错误、空态前提示和局部说明。
  - 不复用全局 `shell-alert-slot`。
- `page-metrics`
  - 放 2 到 4 个紧凑统计卡片。
  - 只展示页面已经真实能拿到的数据。
- `page-body`
  - 主区放表格或关键卡片。
  - 侧区放规则说明、边界提示、空态指引或辅助统计。

## 6. 三张管理页的骨架落点

### 6.1 管理概览页

- `page-header`
  - 说明当前管理面职责和可直接进入的管理入口。
- `page-actions`
  - 保留进入分组管理、进入隧道管理两个快捷动作。
- `page-metrics`
  - 展示初始化状态、会话状态，以及后续可从真实 API 读取的分组/隧道数量。
- `page-body`
  - 主区放“当前能力概览”和“关键入口”。
  - 侧区放“风险提醒 / 当前边界”。

### 6.2 分组管理页

- `page-header`
  - 说明分组管理范围和 token 展示约束。
- `page-actions`
  - `新建分组`
  - `刷新列表`
- `page-metrics`
  - 分组总数
  - 启用分组
  - 停用分组
- `page-body`
  - 主区放分组表格。
  - 侧区放 token 生命周期说明、操作注意事项或空态指引。

### 6.3 隧道管理页

- `page-header`
  - 说明当前支持 TCP/UDP 单端口和范围映射。
- `page-actions`
  - `新建隧道`
  - `刷新列表`
- `page-metrics`
  - 隧道总数
  - 启用隧道
  - 范围映射数量
  - 可选补一项协议分布
- `page-body`
  - 主区放隧道表格。
  - 侧区放映射规则、端口跨度说明和“先建分组再建隧道”的依赖提示。

## 7. 认证页与管理壳层的关系

`/init` 和 `/login` 不进入管理壳层，但需要共用同一套视觉语言：

- 同样的配色、圆角、阴影和背景基调
- 同样的标题层级和提示文本节奏
- 更聚焦的双栏或单栏认证布局

认证页不显示侧边栏和顶部状态区，避免未登录态和已登录管理态混在同一层。

## 8. 响应式约定

- 桌面端
  - 采用固定侧边栏 + 可滚动主内容区。
  - 页面级 `page-body` 优先使用主区 + 侧区双栏。
- 平板端
  - 保留侧边栏，但压缩宽度和卡片间距。
  - `page-metrics` 优先改为两列。
- 手机端
  - 侧边栏折叠为抽屉或覆盖层。
  - 顶部状态区改成纵向堆叠。
  - `page-actions` 改成换行堆叠。
  - `page-body` 收口为单列，表格保留容器内横向滚动。

## 9. 实现约束

为了让后续实现阶段持续可控，本轮壳层重构固定采用下面的代码约束：

- 导航项、页面标题和页面说明统一从路由元数据或单一配置源读取。
- `AppShellView.vue` 只负责管理壳层、会话状态和全局提示，不承接页面业务逻辑。
- `DashboardView.vue`、`ProxyGroupsView.vue`、`TunnelsView.vue` 只负责各自页面内容，不再重复实现壳层级标题区。
- design tokens、全局字体、间距、颜色和阴影在下一步统一下沉到 `main.css` 与共用类名中，本文件只固定信息架构和页面骨架，不提前展开视觉细节。
