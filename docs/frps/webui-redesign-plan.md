# frps WebUI 管理面板继续优化方案

更新时间：2026-04-20

当前定位：上一轮已经落地了统一管理壳层、认证页和三张管理页；本文记录下一轮继续优化时必须遵守的信息架构基线。当前不是重做后端能力，而是在现有实现上继续做减法、合并和空间重分配。

## 1. 当前目标与硬边界

本轮继续优化的目标固定如下：

- 管理登录页收紧为极简认证入口，不再承载操作说明、流程说明或边界说明块。
- 合并“分组管理”和“隧道管理”为同一张高密度管理页。
- 选中特定分组后，在当前页下方展示该分组拥有的隧道配置。
- 参考 1Panel 收紧管理壳层，让导航贴住左侧边栏，把横向空间尽量留给中间内容区。

本轮不允许越过下面这些边界：

- 不改后端 API、认证算法、challenge 登录语义、Cookie 会话模型。
- 不改数据库 schema、控制协议、现有 CRUD 接口契约和真实能力边界。
- 不把未来能力包装成当前已实现入口；当前仍然只有管理认证、分组 CRUD、隧道 CRUD、TCP/UDP、单端口/范围映射。
- 不因为页面合并而改变已有数据模型；分组仍然是隧道归属容器，隧道仍然必须绑定到分组。

## 2. 新壳层方向

当前已落地的壳层会继续保留，但本轮要进一步收紧成更靠近 1Panel 的单侧导航管理布局：

```text
app-shell
├─ shell-sidebar
│  ├─ brand
│  └─ primary-nav
└─ shell-stage
   ├─ shell-topbar
   └─ shell-content
      └─ route-view
```

壳层调整原则如下：

- 左侧边栏只保留品牌和一级导航，不再常驻大段边界说明卡。
- 一级导航块直接贴住左侧边栏，不做悬浮式标签岛；激活态靠背景、边框和字重表达。
- 顶部条收紧为薄顶栏，只承接页面标题、当前会话状态和少量全局动作。
- 主内容区改为更宽的流式容器，优先保证表格、配置列表和编辑入口的横向空间。
- 页面内部默认不再使用“主区 + 常驻右侧说明栏”的双栏结构；说明性内容改为局部提示、空态或紧凑摘要条。

桌面端建议保持下面的空间分配方向：

- 左侧边栏维持窄宽度，仅承接品牌和导航。
- 顶部条高度控制在单层内容范围内，不再堆叠大段描述。
- 主内容区使用流式宽度和较小横向留白，避免表格因为壳层装饰被压缩。

## 3. 导航与路由表达

本轮的导航表达要从“三张并列业务页”收紧为“概览 + 接入管理”两级主入口：

- 概览
  - 路径：`/`
  - 作用：保留系统状态和管理入口总览。
- 接入管理
  - 主路径：`/proxy-groups`
  - 作用：在同一页承接分组管理和隧道管理。

`/tunnels` 不再作为一级导航中的独立主入口。为了降低改造风险并兼容已有访问路径，可以保留它作为兼容入口，但表现层要收敛到同一张“接入管理”页，不再维持独立的主导航语义。

导航元数据仍然统一从单一配置源读取，不能回退到页面模板里分散手写链接。

## 4. 极简登录页基线

`/login` 仍然独立于管理壳层，但本轮表现层要进一步收紧到极简状态。

默认布局只保留一张认证卡，核心元素只有：

- 大标题
- 管理密钥输入框
- 登录按钮

其他规则如下：

- 不再展示静态“操作说明”“流程说明”“当前边界”“登录后去向”等说明块。
- 不再常驻展示 challenge 计算过程、Cookie 说明或 `auth.json` 重置说明；这些语义保留在实现中，不保留在页面正文里。
- 如果登录失败、状态读取失败或未初始化，需要通过最小化的动态提示表达，但不恢复成说明型页面。
- challenge 请求、proof 计算、登录成功后的 redirect 逻辑、未初始化时的路由守卫跳转都保持原样。

## 5. 合并后的接入管理页

“分组管理”和“隧道管理”合并后，页面固定采用上下主从结构，而不是左右并排的两块大面板。

建议骨架如下：

```text
access-management-page
├─ page-toolbar
├─ group-section
│  ├─ group-summary-strip
│  ├─ group-table
│  └─ group-dialogs
└─ tunnel-section
   ├─ selected-group-header
   ├─ tunnel-summary-strip
   ├─ tunnel-table
   └─ tunnel-dialogs
```

### 5.1 分组区职责

- 页面上半部分先展示分组列表、分组状态和分组级操作。
- 分组行本身承担“选择当前分组”的职责，当前选中态必须清晰可见。
- 分组区继续负责新建、编辑、删除、重置 token 等分组级 CRUD。
- 列表仍然只展示 `token_id` 这类真实存在的摘要，不回显历史明文 token。

### 5.2 隧道区职责

- 页面下半部分只展示“当前选中分组”的隧道配置，不再显示跨分组的全量隧道主表。
- 隧道区标题必须明确当前上下文，例如“分组 A 的隧道配置”。
- 在当前分组上下文中执行新建隧道时，`groupId` 默认绑定到当前选中分组。
- 隧道区继续承接 TCP/UDP、单端口/范围映射、启停状态和删除/编辑操作，但这些动作都受当前选中分组约束。

### 5.3 选中分组后的联动约定

- 分组选中态是下方隧道区唯一的数据上下文来源。
- 页面加载完成后，如果存在分组，应默认选中一个可用分组，避免下半区长期空白。
- 删除当前选中分组后，选中态自动回退到相邻分组；如果已经没有分组，下半区显示“需先创建分组”的空态。
- 刷新分组列表或隧道列表时，优先保留当前选中分组；只有在该分组已不存在时才切换选中目标。

## 6. 页面密度与视觉取舍

这轮优化的核心不是增加信息，而是压缩说明性噪音，把空间还给实际管理对象。

因此页面视觉上要遵守下面这些取舍：

- 不再使用大段 hero 文案、流程说明块或右侧常驻说明栏。
- 页面摘要优先改成紧凑统计条、局部状态标签或短句提示，不再堆叠多张说明卡。
- 表格和配置块尽量全宽展示，减少装饰性留白。
- 页面标题区保留必要标题和动作，不再塞入长副标题。
- 概览页仍可保留适量摘要卡，但分组与隧道合并页要优先服务于“选中、查看、编辑、删除”这条主操作流。

## 7. 响应式约定

- 桌面端
  - 保持固定左侧导航和宽主内容区。
  - 合并页按“上方分组、下方隧道”的单列主轴展开。
- 平板端
  - 保留左侧导航但进一步压缩宽度。
  - 分组区和隧道区继续纵向排列，工具条允许换行。
- 手机端
  - 左侧导航折叠为抽屉。
  - 登录页保持单卡片单列。
  - 合并页中的表格允许横向滚动，但页面结构仍维持先分组后隧道的顺序。

## 8. 实现约束

后续代码落地时必须继续满足下面这些约束：

- 路由元数据、导航标签和页面标题继续统一从单一配置源读取。
- `AppShellView.vue` 只负责壳层、导航和会话动作，不承接分组或隧道业务逻辑。
- 合并页优先复用已有分组 CRUD 和隧道 CRUD 数据结构，不为了前端排版改动接口语义。
- 登录页只做表现层减法，不改 `auth` store 的初始化、bootstrap、challenge 登录和会话恢复流程。
- 正式实现时，如果某些旧页面路由仍需兼容，兼容逻辑应收口在路由层或统一页面层，而不是复制出第二套业务界面。
