# 仪表盘页面设计规范

更新时间：2026-04-21

本文档定义 `/dashboard` 页面的设计基线，包括展示内容、数据来源和边界约束。

---

## 1. 页面定位

仪表盘是用户登录后的首个信息中枢，展示本机网络状态和系统核心统计。

---

## 2. 展示内容

### 2.1 网卡信息

展示本机所有网卡及其 IP 地址：

| 列 | 说明 |
|----|------|
| 网卡名称 | 如 `eth0`、`ens33`、`lo` 等 |
| IP 地址 | 该网卡绑定的所有 IPv4/IPv6 地址，多个 IP 换行展示 |
| 接收数据 | 该网卡总接收字节数（格式化为可读单位） |
| 发送数据 | 该网卡总发送字节数（格式化为可读单位） |

> **注意**：Linux 主机一个网卡可能绑定多个 IP 地址（IPv4 和 IPv6、或多个 IPv4），需在表格中支持多行展示。

数据来源：`GET /api/v1/system/network-interfaces`（需新增）

### 2.2 统计卡片

展示两个核心统计数据：

| 卡片 | 数据来源 | 说明 |
|------|----------|------|
| 分组总数 | `GET /api/v1/proxy-groups` 返回 `items.length` | 所有分组数量 |
| 隧道总数 | `GET /api/v1/tunnels` 返回 `items.length` | 所有隧道数量 |

### 2.3 隧道协议分布饼图

展示 TCP 和 UDP 隧道的数量占比：

| 数据 | 来源 |
|------|------|
| TCP 隧道数 | `GET /api/v1/tunnels` 过滤 `protocol === 'tcp'` |
| UDP 隧道数 | `GET /api/v1/tunnels` 过滤 `protocol === 'udp'` |

使用饼图可视化展示两种协议的占比。

## 4. 数据来源

### 4.1 现有 API

| API | 用途 |
|-----|------|
| `GET /api/v1/proxy-groups` | 获取分组列表 |
| `GET /api/v1/tunnels` | 获取隧道列表 |

### 4.2 新增 API

| API | 用途 | 返回字段 |
|-----|------|----------|
| `GET /api/v1/system/network-interfaces` | 获取网卡信息 | `name`, `ips[]`（每个元素含 `addr` 和 `family`），`rx_bytes`, `tx_bytes` |

**API 返回示例**：

```json
{
  "items": [
    {
      "name": "eth0",
      "ips": [
        { "addr": "192.168.1.100", "family": "ipv4" },
        { "addr": "10.0.0.50", "family": "ipv4" },
        { "addr": "fe80::a00:27ff:fe4e", "family": "ipv6" }
      ],
      "rx_bytes": 1288490188,
      "tx_bytes": 858993459
    },
    {
      "name": "lo",
      "ips": [
        { "addr": "127.0.0.1", "family": "ipv4" },
        { "addr": "::1", "family": "ipv6" }
      ],
      "rx_bytes": 10485760,
      "tx_bytes": 10485760
    }
  ]
}
```

## 5. 组件选用

| 场景 | 组件 |
|------|------|
| 网卡表格 | `el-table`，IP 地址列使用多行展示 |
| 统计卡片 | `el-card` 或自定义 div |
| 饼图 | ECharts（需引入） |
| 加载态 | `v-loading` 指令 |

---

## 6. 边界约束

- 只展示上述内容，不添加其他信息
- 数据在页面加载时一次性获取
- 不做实时刷新或轮询
- 饼图仅展示协议类型分布，不做其他维度分析
