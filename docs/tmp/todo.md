# 当前轮 Todo

- 进度归档索引：`docs/progress/README.md`

当前总目标：

- 为端口冲突检查与热更新交互整理一份全量测试方案，继续收口剩余可测性基建，为后续具体场景测试落地做准备。

子步骤：

- 场景编排基座：为双进程、双 session、外部占用进程、本机 IP 变化和配置连续变更准备统一脚本化编排器，支持显式步骤、显式放行、显式观测点，避免每个测试各自手搓并发控制。
- 故障注入覆盖表：先列出所有计划支持的注入能力与对应可覆盖的场景类型，明确哪些故障已可稳定制造、哪些仍缺注入点，避免后续写测试时才发现关键场景不可测。
- 稳定性补充层基线：在确定性基建完成后，再补 `-race`、多 `GOMAXPROCS`、高频配置抖动、长稳 soak、双平台回归和资源压力回归入口，但这些入口也必须有明确观测点和失败判定，不允许只做“跑一晚看日志”。
- 可测性验收门槛：任何准备进入正式测试矩阵的场景，先要求能在单机连续复现、在快慢机器上保持同一状态结论、在失败时输出明确状态断言差异；做不到这一点的场景，先回到前置基建补能力。

当前轮边界：

- 当前轮先做实现审查和测试方案设计，不修改业务实现代码。
- 测试方案不局限于现有 `*_test.go`，允许包含脚本化双进程场景、异常注入、双平台验证与长稳回归。
- 讨论范围只聚焦端口冲突检查与热更新交互，不扩展到其他独立功能优化。
- 后续所有可测性基建子步骤统一写入 `docs/frps/testing-infrastructure.md`，不再回填 `docs/frps/testing-debugging.md`。
