# 当前轮 Todo

- 进度归档索引：`docs/progress/README.md`

## 总目标

为 `frps` 增加“分组生效 IP”能力：服务启动后自动采集本机全部网卡与 IPv4/IPv6 地址并持续轮询变化，按 Windows / Linux 分开收口平台实现；数据库为分组增加组级生效 IP 字段，用于约束该分组下所有代理 listener 统一监听到指定本机 IP；WebUI 只允许从服务端当前可用本机 IP 与特殊值 `0.0.0.0`、`::` 中选择；如果数据库中分组当前配置的生效 IP 已不再存在于本机，则分组状态在 WebUI 中显示为异常。

## 子步骤

1. **把分组 listener 绑定到组级生效 IP**：为 `proxy_groups` 增加 `effective_ip` 持久化字段并打通到 `GroupRuntime`；控制面在展开分组下各 tunnel listener 时统一使用该值绑定；若配置值不是当前可用本机 IP 且也不是 `0.0.0.0` / `::`，则不得静默回退到其他地址。

2. **补齐分组运行态异常判定与 WebUI 展示**：管理接口需要返回分组当前生效 IP 可用性和异常原因；WebUI 分组列表、编辑弹窗和相关状态标签需要展示“正常 / 异常”，并明确提示“已配置 IP 当前不存在于本机”这类错误原因。

3. **完成生效 IP 下拉与异常值回显**：WebUI 分组表单把“生效 IP”做成下拉列表，选项只来自当前本机可用 IPv4/IPv6 地址与 `0.0.0.0`、`::`；若数据库已有值已失效，表单仍需以异常态回显该值，避免用户进入编辑态后丢失上下文。

4. **回归与验证**：补齐 schema / API / 控制面 / WebUI 回归，覆盖 Windows / Linux 地址采集差异、轮询后地址消失、异常态展示、下拉限制、IPv4/IPv6 与特殊地址绑定。

## 当前轮边界

- 只做分组级 listener 绑定 IP，不引入隧道级单独绑定 IP。
- 生效 IP 的可选来源以 `frps` 服务端本机地址为准，不依赖 `frpc` 上报信息。
- `0.0.0.0` 与 `::` 视为始终可选的特殊监听值，不归属任何物理网卡。
- IPv4 和 IPv6 都必须进入可选集合；同一网卡上的多地址需要完整保留，不能只取首个地址。
- 数据库中的“生效 IP”是持久化配置；分组“异常”是运行态派生状态，不单独新增持久化异常字段。
- 已配置生效 IP 消失后，系统只标记异常并阻止按该地址继续监听，不自动改写数据库值，不自动切换到其他 IP。
- 继续沿用当前开发阶段约束：不做自动 schema migration；新增列后旧库需要手工补列或重建。
- 本机地址快照层已经落地并会在 `frps` 启动后自动轮询；后续步骤统一复用这份快照，不再新增第二套地址发现逻辑。
