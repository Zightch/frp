# 当前轮 Todo

- 进度归档索引：`docs/progress/README.md`

当前总目标：

- 完成证书 / CA 统一资产层最小闭环：`frps` 首次启动能初始化新资产表并完成启动期证书准备与校验，运行时开放上传 / 粘贴 / 生成相关入口，校验通过后写库，校验失败则返回可直接用于管理面的错误。

子步骤：

- 落库与启动初始化：新增统一证书资产表及必要索引，包含证书哈希字段 `crt_hash`，接入 `frps` 首次启动数据库初始化流程。
- 启动期证书准备：启动时加载系统 CA 和数据库中的证书 / CA 资产，完成链校验、时间合法性检查等启动前准备。
- 启动顺序收口：保持现有端口冲突检查逻辑不变，在启动准备完成后继续放行 `frpc` 登录。
- 资产写入接口：提供上传、手动粘贴、生成相关管理 API，覆盖证书资产与 CA 资产的最小写入路径。
- 写入前校验与错误返回：上传或生成后先做证书有效性检查，校验通过再写库，校验失败返回结构化错误并支持管理面直接弹窗提示。
- 删除接口与影响扫描：提供证书 / CA 资产删除 API，删除前扫描整条下游证书链和直接 / 间接子节点，返回“删除该证书所影响到的子证书”警告信息，供管理面二次确认。
- 管理面最小闭环：接通现有管理入口到上述写入接口，确保成功写入、失败报错两条路径都可验证。

有效检查具体工作：

- 解析检查：`crt`、`key` 必须能被正确解析；当前只接受 `pem`。
- 证书匹配检查：证书资产要求证书公钥与私钥匹配；上传 CA 时如果带 `key`，也要校验与 CA 证书匹配。
- 时间检查：校验 `NotBefore / NotAfter` 合法，拒绝明显未生效、已过期或时间区间异常的资产。
- 基础约束检查：按 `asset_type` 校验基础用途；`ca` 资产必须具备 CA 基本约束，`certificate` 资产不能伪装为 CA。
- 上游链检查：若填写 `issuer_asset_id`，需校验上游存在、类型合法、不能自引用、不能形成环。
- 签发链检查：当资产声明有上游时，需校验当前证书是否可被上游证书正确验签；多级场景递归校验到链顶。
- 链完整性检查：对生成证书或带上游的上传证书，校验从当前资产向上追溯时链条连续，不接受断链资产写库。
- 写库前去重 / 冲突检查：至少拦截同名策略冲突和完全重复内容写入；先计算 `crt_hash` 做快速候选过滤，命中后再做精确内容比对，避免资产层出现明显重复记录。
- 启动期健康检查：数据库中已有资产在启动时逐条复验上述关键规则；失败资产需汇总为明确错误，决定阻断启动还是标记异常后跳过，要在实现时一次收口。
- 错误模型收口：所有校验错误统一为可供管理面直接展示的结构化结果，区分解析失败、链失败、时间失败、约束失败、删除影响提示等类别。

当前轮边界：

- 本轮只落证书 / CA 资产层最小闭环，不展开端口 / SNI / 反代 / WebUI HTTPS / listen 绑定能力。
- 本轮不实现隧道级 CA 池的消费、`frps -> frpc` 的按隧道 CA 下发以及相关协议改造。
- 本轮不改现有端口冲突检查策略，不额外引入新的 `frpc` 登录拦截规则。
- 本轮只支持 `pem` 格式，不做旧版本兼容约定。

当前唯一下一步：

- 梳理并落定统一证书资产表的数据库 schema、初始化入口和最小数据模型，优先收口 `crt_hash` 在 schema 与索引层的落法，作为本轮实现起点。
