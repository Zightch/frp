# 2026-04-27

## 1. `frps/internal/control` 的 `control v2` 重构设计稿已收口到可执行粒度

截至 2026-04-27，当前轮关于 `frps/internal/control` 全量重构的第一步已经完成：仓库内已经新增一份专门服务本轮重构的执行设计稿，明确固定了 `control v2` 的架构边界、ownership 规则、状态模型、事件模型、动作模型和实施顺序，不再继续沿用旧 `control/` 的共享锁拼装思路。

本次新增文档如下：

- `docs/tmp/control-v2-design.md`

本次在设计稿中固定的关键边界如下：

- 新架构总图固定为：
  - `Server`
  - `Supervisor`
  - `SessionAgent`
  - `BindManager`
  - `RuntimeRepo`
- `Server` 只保留接入、transport 协商、登录期认证、帧编解码和事件投递，不再直接推动 runtime 状态。
- `Supervisor` 只负责 agent 注册表、group 级会话接管策略和上游事件路由。
- `SessionAgent` 成为单个 group 的唯一状态写入者；配置状态、runtime 状态、stream 和 udp session 全部通过 agent inbox 串行推进。
- `BindManager` 成为 listener/端口 claim 的唯一 owner；端口冲突必须在 prepare/start 阶段裁决，而不再依赖旧模型里的 runtime scan 事后补洞。
- `RuntimeRepo` 只负责把 DB / 证书绑定投影成不可变的 `DesiredRuntimeSnapshot`。

本次同时确认并固定了下面这些重构原则：

- 不做旧实现兼容，不保留旧的内部状态组织方式。
- 不引入第三方状态机库；状态机只作为仓库内的 typed state/reducer/reconcile 建模手段。
- 不再把 `runtime scan` 作为主恢复链路；后续主恢复路径统一走事件驱动的 `Reconcile`。
- TCP / UDP 仍然分开实现，不做“万能统一 tunnel runtime”。
- 允许后续把“同分组新连接被拒绝”直接替换为“新 session 接管旧 session”。

本次执行情况如下：

- 本次新增执行设计文档，不改正式架构文档口径。
- 本次未运行测试。

## 2. `controlv2/session` 第一批显式状态骨架已落地

截至 2026-04-27，`control v2` 的第一批代码骨架已经落地到新的 `frps/internal/controlv2/session/` 目录，作为后续 `Supervisor`、`BindManager` 和真实连接接入的状态建模基础。

本次新增文件如下：

- `frps/internal/controlv2/session/state.go`
- `frps/internal/controlv2/session/events.go`
- `frps/internal/controlv2/session/actions.go`
- `frps/internal/controlv2/session/reducer.go`
- `frps/internal/controlv2/session/reconcile.go`
- `frps/internal/controlv2/session/reducer_test.go`

本次落地的代码边界如下：

- `state.go`
  - 收口 `SessionPhase`
  - 收口 `RuntimePhase`
  - 收口 `BlockReason`
  - 收口 `BindingPhase`
  - 定义 `SessionState`、`DesiredRuntimeSnapshot`、`PendingConfigPush`、`AppliedRuntimeSnapshot`、`BindingState`、`TCPStreamState`、`UDPSessionState`
- `events.go`
  - 定义 agent 输入事件
  - 覆盖连接附着、配置变化、`config.ack`、binding 结果、TCP accept、UDP datagram、takeover、shutdown、reconcile 请求等最小事件面
- `actions.go`
  - 定义 reducer 输出动作
  - 覆盖 `server.hello`、`config.push`、binding prepare/start/stop、stream/udp 控制消息、连接关闭和 reconcile 调度
- `reducer.go`
  - 建立 `Reduce(state, event) -> (state, actions)` 骨架
  - 固定“事件推进状态，状态只返回动作，不直接做 side effect”
  - 已收进首次附着、期望配置更新、`config.ack`、binding 结果、TCP/UDP 新连接、takeover/shutdown 等关键转移
- `reconcile.go`
  - 建立统一 `Reconcile` 入口
  - 统一处理：
    - `Desired != Applied` 时触发 `config.push`
    - 空配置时收缩 runtime
    - 非空配置但 runtime 未满足时准备 binding
- `reducer_test.go`
  - 新增最小单测骨架，覆盖：
    - `SessionAttached`
    - `ConfigAckReceived`
    - `Reconcile` 推送期望配置
    - `BindingClosed` 触发恢复

本次代码落地同时确认了以下收口：

- 新模型已经开始从“共享可变对象 + 多锁保护”转向“值状态 + 纯转移 + 动作计划”。
- `configVersion / generation` 的旧护栏思路已提升成显式 `Epoch`。
- 当前这批文件只承接 session 状态建模，不接入旧 `app.App`、不替换旧 `control/`，也不进入真实 listener / conn I/O。

本次执行的验证如下：

- `gofmt -w frps/internal/controlv2/session/*.go`

## 3. `SessionAgent`、`Supervisor`、`BindManager` 和 `RuntimeRepo` 的最小执行壳层已落地

截至 2026-04-27，`control v2` 已经不再只是静态状态定义：新的 session actor、group 级 supervisor、最小 bind manager 和 runtime repo 接口骨架已经进入代码库，形成了后续接入真实连接和真实 listener 的第一层执行壳。

本次新增文件如下：

- `frps/internal/controlv2/session/agent.go`
- `frps/internal/controlv2/session/agent_test.go`
- `frps/internal/controlv2/supervisor.go`
- `frps/internal/controlv2/server.go`
- `frps/internal/controlv2/bind/claims.go`
- `frps/internal/controlv2/bind/manager.go`
- `frps/internal/controlv2/bind/manager_test.go`
- `frps/internal/controlv2/repo.go`

本次新增代码固定了下面这些执行边界：

- `session/agent.go`
  - 引入 `session.Executor`
  - 引入 `Agent`
  - 通过带缓冲 inbox 串行消费 `Event`
  - 对 `ActionRequestReconcile` 直接转换成 follow-up event
  - 其余 action 则走 executor 外壳，开始形成“状态机外执行 side effect”的最小实践
- `session/agent_test.go`
  - 新增最小 actor 测试，确认 `SessionAttached -> ActionRequestReconcile -> ReconcileRequested -> PendingConfig` 这条 follow-up 链已经在 agent 内部跑通
- `supervisor.go`
  - 引入 `Supervisor`
  - 固定 `groupID -> agent`、`sessionID -> agent` 两层索引
  - 新登录附着时会向旧 group agent 发送 `SessionTakeoverRequested`
  - 提供 `DispatchBySessionID`、`UpdateDesiredRuntime`、`NotifyNetworkChange`、`SessionState`、`Shutdown` 最小入口
- `server.go`
  - 引入 `controlv2.Server`
  - 当前先作为 `Supervisor + RuntimeRepo` 的薄包装层
  - 提供：
    - `HandleAuthenticatedSession`
    - `Dispatch`
    - `RefreshDesiredRuntimeByGroup`
    - `NotifyNetworkChange`
    - `Shutdown`
- `bind/claims.go` + `bind/manager.go`
  - 引入 `ExpandBindings`
  - 引入 `ClaimOwner`
  - 引入 `MemoryManager`
  - 当前内存实现已经能完成：
    - prepare 端口展开
    - start claim
    - stop release
    - 冲突时报 `ErrBindingConflict`
- `bind/manager_test.go`
  - 新增最小回归，覆盖 prepare/start/冲突/stop
- `repo.go`
  - 引入 `RuntimeRepo` 接口，固定 `LoadDesiredRuntimeByClientID / GroupID / ListDesiredRuntimes` 三个最小读取入口

本次同时确认并固定了下面这些收口：

- `control v2` 的下一层实现不会再从旧 `control/` 里借用共享 session 状态对象。
- `Supervisor` 是 group 级单 writer 路由入口，后续 `server.go` 接线时应先把 transport/auth 后的连接事件送到这里。
- `controlv2.Server` 已经成为后续 `app.App` 接线时的第一层对接对象，不再要求 `app.App` 直接拼装 session agent 或 repo。
- `BindManager` 当前先以内存 claim 实现入场；后续接真实 `net.Listener` 时，冲突裁决入口仍保持不变。
