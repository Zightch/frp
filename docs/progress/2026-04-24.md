本次完成的实现如下：

- `frps/internal/control/refresh.go`
  - 删除“`ClientSecretHash` 变化就立即关闭在线 session”的特判分支。
  - 当前只要隧道快照、`effective_ip` 等运行时条件没有要求 reload / rebind，刷新会走既有的 `keep_runtime` 路径，在线 `frpc` 保持连接不变。
- `frps/internal/control/server_test.go`
  - 旧测试 `TestServerRefreshGroupClosesSessionAfterTokenReset` 已改成新语义：
    - 重置 key 后当前在线 session 不收到关闭帧
    - 当前在线 session 心跳仍正常
    - 旧 key 在下一次登录时会被拒绝
    - 新 key 在下一次登录时可以成功通过认证
  - 同时补了两个通用测试 helper，用于复用“预期登录失败”和“心跳保活”断言。

本次确认并收束的边界如下：

- 当前在线 `frpc` 仍然只会因为既有的 runtime reload / rebind / pending-config 冲突 / 删除分组等原因被关闭，不会因为单独重置 key 而被立刻踢线。
- 当前新 key 的生效点已经收口为“下一次登录校验”；也就是旧连接保活，重连或新建登录必须使用新 key。
