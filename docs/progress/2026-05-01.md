## 限速底层纯组件收口

- `frps/pkg/ratepolicy` 现已继续下沉最小纯组件：
  - `Direction`
  - `BucketConfig`
  - `TokenBucket`
  - `LimiterRegistry`
  - `WaitN / context cancel`
- `BucketConfig` 当前固定：
  - 输入基础速率单位仍是 `bps`
  - 内部 burst 不对外配置，按 `RateBPS / 8` 自动换算为默认字节 burst，并保证最小为 `1`
- `TokenBucket` 当前固定为：
  - 基于令牌桶速率控制
  - 正积累受 burst 上限限制
  - 单次 `WaitN` 允许大于 burst，不做“超 burst 直接拒绝”，而是继续等待推进
  - `context cancel` 会退出当前等待
- `LimiterRegistry` 当前固定为：
  - `independent` 按 `tunnel_id + direction` 独立建桶
  - `shared` 按 `policy_id + direction` 共享建桶
  - 同一 registry key 如果配置不一致，直接报错，不允许静默分叉
- 当前这层仍保持纯组件边界：
  - 不接 `control`
  - 不接 `session`
  - 不接 `TCP / UDP` 数据面 copy loop
  - 不引入单独的 `independent` / `shared` 双套实现

## 限速真正接进 `frps` TCP 数据面

- `frps/pkg/ratepolicy` 继续维持底层纯组件边界，但当前已补齐统一写入协作件：
  - `Limiter` 接口
  - `TunnelLimiters`
  - `ChunkSize`
  - `WritePayload`
- `TunnelLimiters` 不再把上层运行时绑死到 `TokenBucket` 具体实现，当前 `frps` 数据面和测试桩都只依赖 `Limiter` 接口。
- `frps/internal/control/wiring` 当前已把限速执行上下文正式投影到 session runtime：
  - 每个 session 持有一个 `LimiterRegistry`
  - 每个 public TCP stream 建立一个可取消 `context`
  - `ClosePublicStream` 时取消该 stream 等待
  - `FreezeTunnelRuntime` 时整体取消当前 runtime 下全部等待，并重建 registry
- `frps/internal/control/runtime/serve/tcp` 当前已把限速真正接进 TCP 数据面，而且只放在 `frps`：
  - 下行：公网 TCP -> `stream.data`
  - 上行：`stream.data` -> 公网 TCP
  - 大块 payload 会按 limiter burst 自动切片推进
  - `reload / shutdown / stream close` 通过 session stream context 退出等待，不再额外散落取消逻辑
- 当前边界已明确收住：
  - `frpc` 不执行任何限速逻辑，仍保持轻量转发角色
  - 本子步骤只覆盖单端口 TCP
  - UDP 和 range 仍留待后续子步骤

## 限速收口到 `frps` 权威侧并接进 UDP 数据面

- 当前正式边界已继续收紧：
  - `frpc` 不执行限速
  - `frpc` 不再接收限速字段
  - 限速权威逻辑固定只放在 `frps`
- `frps/pkg/protocol` 当前已移除 `config.push` wire 中的限速字段编码：
  - `protocol.TunnelEntry.RatePolicy` 继续保留在 `frps` 本地运行态结构中
  - 但 `config.push` / `config.ack` 同步链路不再把这组字段下发给 `frpc`
- `frpc` 当前已收掉所有限速下发表面支持：
  - 不再校验 `config.push` 中的限速字段
  - reload 判断不再把限速字段视为 `frpc` 本地执行配置
  - 当前只保留完成本地 TCP / UDP 转发所需的最小配置
- `frps/internal/control/wiring` 当前已把限速执行上下文进一步收口成统一运行态登记：
  - TCP `stream`
  - UDP `session`
  - 两者都走同一套 session 级 `LimiterRegistry`、context 取消和 runtime reset
- `frps/internal/control/runtime/serve/udp` 当前已把限速真正接进 UDP 数据面，而且只放在 `frps`：
  - 下行：公网 UDP ingress -> `udp.data`
  - 上行：`udp.data` -> 公网 UDP listener
  - UDP 固定整包等待、整包转发，不拆 datagram
  - `udp.close` / session close / reload / shutdown 会取消等待
- UDP idle cleanup 当前已与限速等待并存：
  - 活跃传输中的 UDP session 不会被 idle cleanup 抢先回收
  - 真正进入 idle cleanup 的 session 会同步取消对应限速上下文
- 当前支持范围继续固定：
  - 单端口 TCP
  - 单端口 UDP
  - `independent`
  - `shared`
  - range tunnel 仍不进入限速执行
