# 2026-05-01

## 限速策略 `schema + API` 闸口

- 已新增底层纯组件 `frps/pkg/ratepolicy`，当前只承接：
  - `mode = independent | shared`
  - `K / M / G -> bps` 归一
- 已新增正式表并接入 schema 校验：
  - `rate_policies`
  - `rate_policy_bindings`
- 已新增独立管理 API 模块 `frps/internal/api/ratepolicy`，当前开放：
  - `GET /api/v1/rate-policies`
  - `POST /api/v1/rate-policies`
  - `PATCH /api/v1/rate-policies/{id}`
  - `DELETE /api/v1/rate-policies/{id}`
  - `GET /api/v1/rate-policies/{id}/bindings`
  - `POST /api/v1/rate-policies/{id}/bindings`
  - `DELETE /api/v1/rate-policies/{id}/bindings/{tunnel_id}`
- 当前边界已经在 API 入口收住：
  - 只允许绑定单端口 TCP / UDP 隧道
  - range 隧道不可绑定
  - 一个隧道最多绑定一个限速策略
  - `name / mode / value / unit` 非法值在入口拒绝
  - 删除仍有 binding 的策略默认拒绝
- 已补齐与旧资源的耦合收口：
  - 删除隧道时自动删除 `rate_policy_bindings`
  - 删除 `proxy_group` 时，其下隧道和 `rate_policy_bindings` 一起删除
  - 已绑定限速策略的隧道不允许直接改成 `remote_type=range`
- 已同步正式文档：
  - `docs/project-overview.md`
  - `docs/frps/design/rate-policy.md`
  - `docs/frps/technical/data-model.md`
  - `docs/frps/technical/management-api.md`

## 限速策略进入运行时快照和下发链路

- `frps/internal/control/repo` 已在加载 `GroupRuntime` 时联表读取：
  - `tunnels`
  - `rate_policy_bindings`
  - `rate_policies`
- 每条 tunnel 当前都会直接投影出最终执行限速字段，并进入：
  - `GroupRuntime`
  - `ConfigSnapshot`
  - `protocol.ConfigPush`
  - `protocol.TunnelEntry`
- 当前下发的最小执行字段固定为：
  - `policy_id`
  - `mode`
  - `downlink_bps`
  - `uplink_bps`
- `snapshot version` 和 `tunnel revision` 现在都会纳入：
  - `tunnels.updated_at`
  - `rate_policy_bindings.updated_at`
  - `rate_policies.updated_at`
- `frps` 控制域快照比较和 `frpc` 热重载比较，现已把限速执行字段纳入“隧道是否变化”的唯一判断。
- `frpc` 对新字段的边界校验已补齐：
  - 未绑定策略时，限速字段必须全零
  - 已绑定策略时，`mode` 必须合法
  - 上下行 `bps` 必须都为正
  - range tunnel 不允许携带限速策略执行字段
- 已同步正式文档：
  - `docs/project-overview.md`
  - `docs/frps/design/rate-policy.md`
  - `docs/frps/features/control-and-data-plane.md`
